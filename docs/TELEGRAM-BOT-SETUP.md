# Telegram-бот для уведомлений о заявках: пошагово с проверками

Бэкенд AGAPE после сохранения заявки (`POST /api/contact`) отправляет сообщение в Telegram через [Bot API](https://core.telegram.org/bots/api), если заданы переменные **`TELEGRAM_BOT_TOKEN`** и **`TELEGRAM_CHAT_ID`** в `backend/.env`.

Ниже — создание бота, получение `chat_id`, ручная проверка и связка с сервером. На **каждом шаге** есть блок **«Проверка»**: пока он не зелёный, переходить дальше не нужно.

---

## Шаг 1. Создать бота и получить токен

1. Откройте Telegram и найдите **[@BotFather](https://t.me/BotFather)**.
2. Отправьте команду **`/newbot`** (или используйте уже существующего бота и **`/token`** для выдачи нового токена).
3. Задайте **имя** бота (как он отображается в списке чатов) и **username** (должен заканчиваться на `bot`, например `agape_leads_bot`).
4. BotFather пришлёт **токен** вида `123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

**Проверка (обязательно):** подставьте токен в URL и откройте в браузере или выполните:

```bash
curl -s "https://api.telegram.org/botВАШ_ТОКЕН/getMe"
```

Ожидается JSON с **`"ok":true`** и блоком **`result`** с `username`, `id` бота.  
Если **`"ok":false`** — токен скопирован с ошибкой или отозван; запросите новый у BotFather.

---

## Шаг 2. Выбрать, куда слать уведомления

Возможны два типичных варианта.

### Вариант A: личные сообщения вам

1. Найдите своего бота по **username** и нажмите **Start** или отправьте любое сообщение (например `/start`).
2. Нужно узнать **ваш** числовой `chat_id` (не путать с `id` бота из `getMe`).

**Проверка — получить `chat_id`:**

```bash
curl -s "https://api.telegram.org/botВАШ_ТОКЕН/getUpdates"
```

В ответе найдите объект **`"chat":{"id": НОМЕР, ...}`** — для лички это **положительное** число (часто 9–10 цифр). Это и есть **`TELEGRAM_CHAT_ID`**.

Если **`"result":[]`** пустой — вы ещё **не писали боту** с аккаунта, с которого хотите получать уведомления. Напишите боту снова и повторите `getUpdates`.

### Вариант B: группа или супергруппа

1. Создайте группу в Telegram, добавьте в неё **вашего бота** (через «Добавить участников»).
2. **Опционально, но удобно:** назначьте бота **администратором** с правом отправлять сообщения (обычно достаточно стандартных прав).
3. Напишите **любое сообщение в группе** (можно от себя), чтобы в чате появилась активность.

**Проверка — `chat_id` группы:**

```bash
curl -s "https://api.telegram.org/botВАШ_ТОКЕН/getUpdates"
```

Ищите `"chat":{"id": ...` для **этой группы**. У супергрупп и каналов `id` обычно **отрицательный**, часто начинается с **`-100`**.

Если обновлений нет: убедитесь, что сообщение отправлено **после** добавления бота; при необходимости удалите бота из группы, добавьте снова, напишите в чат и повторите `getUpdates`.

## Шаг 3. Ручная отправка тестового сообщения

Подставьте **токен** и **chat_id** из шагов 1–2:

```bash
curl -s -X POST "https://api.telegram.org/botВАШ_ТОКЕН/sendMessage" \
  -H "Content-Type: application/json" \
  -d '{"chat_id":"ВАШ_CHAT_ID","text":"Тест AGAPE: бот и чат настроены."}'
```

**Проверка:** в ответе **`"ok":true`**, в Telegram приходит сообщение.

Частые ошибки в `description`:

| Текст от API | Что сделать |
|--------------|-------------|
| `chat not found` | Неверный `chat_id` или бот не в группе / с ним не начинали диалог |
| `Unauthorized` | Неверный токен |
| `bot was blocked by the user` | Разблокируйте бота в личке |

Бэкенд использует тот же метод `sendMessage` и режим разметки **HTML** для текста заявки; ручной тест выше — без HTML, этого достаточно для проверки доставки.

## Шаг 4. Прописать переменные в бэкенде

В **`backend/.env`** (на VPS: `/var/www/agape/backend/.env`):

```env
TELEGRAM_BOT_TOKEN=123456789:AAH...ваш_полный_токен...
TELEGRAM_CHAT_ID=123456789
```

Для группы `TELEGRAM_CHAT_ID` указывайте **как в JSON** — отрицательное число **в кавычках не нужно** в `.env`, достаточно:

```env
TELEGRAM_CHAT_ID=-1001234567890
```

**Проверка локально (без systemd):**

```bash
cd backend
# убедитесь, что в .env заданы TELEGRAM_* и остальной минимум (PORT, DATABASE_URL, CORS_ORIGINS)
set -a && source .env && set +a
go run ./cmd/server/main.go
```

В другом терминале:

```bash
curl -s -X POST http://127.0.0.1:8080/api/contact \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест TG","email":"test@example.com","phone":"","message":"Проверка из curl"}'
```

Ожидается ответ **`201`** с `success: true`. В Telegram должно прийти сообщение с полями заявки.  
Если **201 есть**, а **Telegram пуст** — смотрите логи процесса: строки уровня **`telegram notify`** с ошибкой.

**Проверка на VPS с systemd:**

```bash
sudo nano /var/www/agape/backend/.env   # добавить TELEGRAM_*
sudo systemctl restart agape-backend
sudo journalctl -u agape-backend -f
```

Отправьте заявку с сайта или через `curl` на `https://agapedesign.ru/api/contact`. В логе не должно быть ошибки после сохранения заявки; в Telegram — новое сообщение.

## Шаг 5. Итоговый контрольный список

| # | Действие | Критерий успеха |
|---|----------|-----------------|
| 1 | `getMe` | `"ok": true` |
| 2 | `getUpdates` после сообщения в нужный чат | Виден `chat.id` |
| 3 | Ручной `sendMessage` через `curl` | Сообщение в чате |
| 4 | `.env` + перезапуск бэкенда | `POST /api/contact` → 201 |
| 5 | Реальная форма на сайте | Заявка в БД и сообщение в Telegram |

---

## Безопасность

- **Не коммитьте** токен в git. Файл `.env` на сервере — права **`chmod 600`**.
- Если токен утёк — в BotFather **`/revoke`**, затем обновите `TELEGRAM_BOT_TOKEN` и перезапустите сервис.

---

## Отключить уведомления

Удалите переменные **`TELEGRAM_BOT_TOKEN`** и **`TELEGRAM_CHAT_ID`** из `.env` (или оставьте пустыми) и перезапустите бэкенд. Заявки по-прежнему сохраняются в SQLite.

### Не путать с `LEADS_ADMIN_TOKEN`

**`LEADS_ADMIN_TOKEN`** — это **не** токен BotFather и **не** часть Telegram. Это **ваш собственный секрет** для защиты HTTP-эндпоинтов списка заявок (`GET` / `PATCH` `/api/leads`).

**Чем заполнить:** любая длинная неугадываемая строка. Удобно сгенерировать один раз:

```bash
openssl rand -hex 32
```

Скопируйте вывод в `backend/.env` как значение `LEADS_ADMIN_TOKEN` (без кавычек, без пробелов). При запросах к `/api/leads` указывайте тот же текст:

`Authorization: Bearer <то_что_в_LEADS_ADMIN_TOKEN>`

Если переменная пустая — админ-роуты заявок отключены (ответ `503`). Подробнее: [BACKEND.md](./BACKEND.md) (раздел «Заявки для работы с клиентами»).
